# 07. 포트폴리오 구조 제안

## 전체 방향
이 포트폴리오는 “눈에 띄는 개인 홈페이지”보다  
**채용 담당자가 빠르게 읽는 기술 이력서 + 프로젝트 노트**에 가까워야 한다.

## 추천 페이지 구조

### 1) Home
가장 중요한 페이지.

#### 포함 요소
- 이름 / 한 줄 포지셔닝
- 짧은 소개 2~3문장
- 핵심 키워드
- 대표 프로젝트 2~4개
- 수상/문제 해결 요약
- GitHub / Resume / Contact

#### 반드시 보여줘야 하는 것
- 시스템 소프트웨어 지향
- C/C++ 중심
- OS / Linux / 메모리 관심
- 알고리즘 기반 문제 해결력

---

### 2) About
#### 포함 요소
- 왜 이 방향을 택했는지
- 어떤 문제를 좋아하는지
- 어떤 방식으로 학습하는지
- 인턴이 없더라도 어떤 근거로 성장 가능성을 보여줄지

#### 핵심 메시지
- 만드는 것보다 원리와 구조를 파고드는 편
- 알고리즘과 시스템 과제가 연결되어 있음
- 코드 분석과 최적화에 끌림

---

### 3) Projects
#### 구성 원칙
- 많아도 4~5개
- 대표 프로젝트 2~3개는 강하게
- 시스템 관련 프로젝트를 위에
- 서비스/프론트 프로젝트는 아래

#### 각 카드에 필요한 요소
- 제목
- 한 줄 설명
- 역할
- 기술 스택
- 링크
- 짧은 결과

#### 상세 페이지 권장 템플릿
1. 배경
2. 목표/문제
3. 내가 맡은 역할
4. 구현/수정 내용
5. 기술적으로 어려웠던 점
6. 결과
7. 배운 점

---

### 4) Problem Solving
이 사용자는 이 섹션이 필요하다.

#### 포함 요소
- SCON, SCPC
- Baekjoon / Codeforces
- 문제 해결을 통해 길러진 사고 방식
- 시스템/최적화와 연결되는 해석

#### 주의점
- 랭크 자랑 페이지처럼 보이면 안 됨
- “문제를 빨리 푼다”보다 “구조를 읽고 최적화를 고민한다”로 연결

## 추천하지 않는 구성
- 소개보다 애니메이션이 더 많은 구조
- 하루 단위 학습 로그 중심 블로그형 첫 화면
- Skill만 잔뜩 나열하는 페이지
- 프로젝트 8개 이상 전시
- 쓸데없이 화려한 자기소개 문장
