# 08. 문구 작성 규칙

## 기본 톤
- 짧고 단정하게
- 과장 없이
- 기술적 근거 중심으로
- 사용자의 말투를 너무 캐주얼하게 복제하지는 말 것
- 그러나 지나치게 기업 홍보문처럼 쓰지도 말 것

## 문구에서 강조할 것
- 문제 해결력
- 로우레벨 관심
- 운영체제/메모리 이해
- 코드 분석 성향
- 꾸준한 학습과 복기

## 문구에서 줄일 것
- 막연한 열정
- “도전정신”, “성실함”, “책임감” 같은 추상어 남발
- 근거 없는 리더십
- 범용 개발자 이미지

## 금지 규칙
- 없는 수치 쓰기
- 없는 성능 개선 쓰기
- 없는 협업 툴/기술 스택 쓰기
- 불확실한 사실을 확정 어조로 쓰기
- 회사 맞춤 자소서 문구를 포트폴리오 본문에 섞기

## 좋은 문장 패턴
- “운영체제 과제를 통해 스케줄링과 메모리 관리 흐름을 직접 수정해 보았습니다.”
- “알고리즘 경험은 복잡한 문제를 빠르게 구조화하는 데 도움이 되었습니다.”
- “저는 서비스 기능보다 시스템이 왜 그렇게 동작하는지에 더 끌리는 편입니다.”

## 나쁜 문장 패턴
- “다양한 기술을 활용해 혁신적인 서비스를 만들었습니다.”
- “어떤 문제든 해결할 수 있는 개발자입니다.”
- “열정과 책임감으로 최고의 성과를 내겠습니다.”
- “프론트엔드부터 백엔드, AI까지 폭넓게 다룹니다.” (근거 없으면 금지)

## 프로젝트 설명 템플릿
### 한 줄 요약
무엇을 했는지 + 왜 중요한지

### 본문 구조
1. 배경
2. 목표
3. 내가 맡은 일
4. 기술적 포인트
5. 결과
6. 배운 점

## 카드 설명 템플릿
- `xv6의 스케줄러와 메모리 관련 코드를 수정하며 운영체제 내부 흐름을 직접 다뤄본 프로젝트`
- `uftrace 트랙 참여를 통해 실행 흐름 추적 도구와 오픈소스 협업 과정을 배운 경험`

## 자기소개 요약 템플릿
- `알고리즘 기반 문제 해결력과 운영체제 관심을 바탕으로 시스템 소프트웨어 직무를 준비하고 있습니다.`
- `C/C++ 중심의 로우레벨 개발과 코드 분석, 성능 최적화에 관심이 많습니다.`

## 시각 요소 문구 규칙
- 배지는 많아도 5~7개
- 과장된 슬로건 금지
- 제목은 짧게
- 본문은 2~4문장 단위로 끊기
