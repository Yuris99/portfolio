# 02. 직무 포지셔닝

## 1순위 포지션
- 시스템 소프트웨어
- 로우레벨 소프트웨어
- C/C++ 기반 개발
- 운영체제, 메모리, 성능 최적화와 가까운 직무
- 코드 분석 / 검증 / 품질 / 인프라 내부 로직과 맞닿은 역할

## 2순위 포지션
- 펌웨어/임베디드와 맞닿은 일부 직무
- 검증/분석 성격이 있는 SW 직무
- Linux 기반 개발 직무
- 반도체/메모리와 SW가 닿는 응용 엔지니어링 계열

## 이 사용자에게 맞는 이유
### 1) 알고리즘 실력이 단순 취미가 아니라 문제 해결력의 증거
이 사용자는 알고리즘을 오래 했고, 대회 성과도 있다.  
이 점은 “코딩 테스트 잘 봄”에서 끝내지 말고 아래처럼 해석해야 한다.

- 제한된 시간 안에 핵심을 파악함
- 최적화 관점을 익힘
- 코드 구조를 빠르게 읽고 판단함
- 난도가 높은 문제를 오래 붙들 수 있음

### 2) OS / 메모리 / Linux로 관심이 이어짐
운영체제 수업, xv6 과제, 메모리 관련 논문 탐독, uftrace 경험 등은  
이 사용자의 관심이 단순히 앱 구현이 아니라 **시스템 내부 동작** 쪽에 있음을 보여준다.

### 3) 코드 분석형 성향과 잘 맞음
새로운 기능만 만드는 것보다, 기존 시스템을 뜯어보고 동작 원리를 이해하고 개선 포인트를 찾는 쪽이 강점이다.

## 포트폴리오에서 피해야 할 포지셔닝
- 트렌디한 프론트엔드 중심 인재처럼 보이기
- 백엔드 범용 개발자로 뭉뚱그리기
- “무엇이든 다 잘하는 개발자”처럼 보이기
- 근거 없는 제품 감각/PM 성향 강조

## 추천 자기소개 축
다음 문장 축을 기본으로 삼는다.

- “알고리즘으로 길러 온 문제 해결력”
- “운영체제와 메모리 구조에 대한 관심”
- “C/C++ 중심 로우레벨 개발 지향”
- “코드 분석과 최적화에 강점”
- “Linux와 오픈소스를 통해 내부 원리를 익히는 중”

## 약점 보완 전략
인턴이 없으므로 아래를 더 선명하게 보여줘야 한다.

- 무엇을 공부했는지
- 무엇을 직접 수정/구현했는지
- 왜 그 주제에 꽂혔는지
- 어떤 기술적 관점을 갖고 있는지

즉, 포트폴리오의 승부 포인트는
**경력의 양이 아니라 방향성과 해석력**이다.
