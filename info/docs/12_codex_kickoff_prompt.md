# 12. Codex 시작 프롬프트

아래 문장을 Codex 첫 요청으로 사용한다.

---

이 레포는 홍지훈의 취업용 포트폴리오 사이트다.

반드시 먼저 다음 파일들을 읽어라.

1. `AGENTS.md`
2. `info/Projects.md`
3. `info/자소서 모음.md`
4. `docs/01_profile.md`
5. `docs/04_experience_awards.md`
6. `docs/05_project_bank.md`
7. `docs/06_story_bank.md`
8. `docs/07_portfolio_structure.md`
9. `docs/08_writing_rules.md`
10. `docs/09_copy_drafts.md`
11. `docs/10_todo_verify.md`

이 사용자는 다음 방향으로 포트폴리오를 만들고자 한다.

- 시스템 소프트웨어 / 로우레벨 / 운영체제 / 메모리 / 성능 최적화 지향
- C/C++ 중심
- 알고리즘 기반 문제 해결력 강점
- 코드 분석과 검증을 중요하게 생각함
- 화려한 브랜딩보다 채용 담당자 관점의 정보 전달을 우선함

중요 규칙:
- 없는 경험, 수치, 역할, 기간을 만들지 마라.
- 모호한 사실은 `검증 필요`로 남겨라.
- 서비스 프로젝트를 넣더라도 문제-역할-기술-검증-배운 점 구조로 정리하라.
- WOL Docker, Checkhouse, Manbo는 현재 포트폴리오의 주요 후보 프로젝트다.
- Family Community, boothmap은 공개 범위와 실제 기여 범위를 확인하기 전까지 보조 후보로만 다뤄라.
- xv6 / uftrace / Problem Solving 섹션은 핵심 축이다.

첫 작업으로 아래를 해라.

1. 현재 코드베이스 구조를 파악한다.
2. 기존 포트폴리오 페이지가 있다면 섹션 구성과 정보 누락을 진단한다.
3. `docs/05_project_bank.md` 기준으로 대표 프로젝트 4~5개를 배치하는 홈 구조 개편안을 제안한다.
4. 과장 없이 바로 반영 가능한 수정부터 작은 단위로 진행한다.
