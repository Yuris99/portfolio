## 1. 최우선 목표
포트폴리오는 화려한 개인 브랜딩 사이트가 아니라, 채용 담당자가 1~2분 안에 아래를 이해하게 만드는 문서형 사이트여야 한다.

- 누구인지
- 어떤 직무를 노리는지
- 왜 그 직무에 맞는지
- 어떤 프로젝트/경험이 그 근거인지
- 어떤 기술을 어느 정도까지 다뤘는지

## 2. 사용자 포지셔닝
이 사용자를 아래 축으로 표현하라.

- 시스템 소프트웨어 지향
- 로우레벨 / 운영체제 / 메모리 / 성능 최적화 관심
- C / C++ 중심
- 알고리즘 문제 해결 능력 강점
- 코드 분석과 검증, 원리 이해를 좋아함
- Linux / 오픈소스 / 커널 학습 관심

반대로 아래처럼 포장하지 마라.

- 풀스택 개발자
- 서비스 기획형 개발자
- 화려한 프로덕트 디자이너형 개발자
- 근거 없는 “문제를 모두 해결하는 개발자”
- 인턴/연구 경험이 있는 것처럼 보이게 하는 표현

## 3. 사실성 규칙
절대 지키기.

- 존재하지 않는 프로젝트를 만들지 말 것
- 정확한 수치/기간/수상명/역할이 없으면 추정하지 말 것
- 불명확하면 `TODO`, `검증 필요`, `링크 필요`로 둘 것
- 프로젝트 설명에서 성능 개선 수치가 없으면 수치형 임팩트를 쓰지 말 것
- “주도했다”, “리드했다”는 표현은 증거가 있을 때만 사용할 것
- `vibe coding` 또는 AI 도움을 받은 프로젝트는 숨기지 말되, **직접 이해하고 수정한 범위만** 역량으로 표현할 것
- Checkhouse 사례에서 “AI가 다 망쳤다” 식의 책임 전가 표현 금지
- Manbo 사례에서 “내가 다 했다” 식의 과장 금지
- 해커톤 수상명은 자료마다 차이가 있으므로 현재는 검증 전제로 다룰 것
- 군 보직(소총수/기관총수/분대장)은 자료가 혼재하므로 세부 표현은 검증 전까지 최소화할 것

## 4. 구현 원칙
- 기존 프레임워크와 디렉터리 구조를 우선 존중할 것
- 사용자가 명시하지 않으면 스택 마이그레이션 금지
- 디자인보다 정보 구조를 먼저 고칠 것
- 과한 애니메이션, 과한 글래스모피즘, 읽기 어려운 UI 금지
- 다크모드는 있으면 좋지만 내용 전달을 해치면 안 됨
- 모바일/데스크톱 반응형은 필요하지만, 포트폴리오의 핵심은 데스크톱 가독성

## 5. 문구 원칙
- 기본 언어는 한국어
- 필요 시 영문 이름/직무명 병기 가능
- 문장은 짧고 단정하게
- 아부, 과장, 추상적 열정 표현 금지
- “열정적인”, “도전적인”, “성실한” 같은 단어는 구체적 근거가 있을 때만 사용
- 알고리즘은 “코테용 취미”가 아니라 **문제 분석과 최적화 사고의 근거**로 연결할 것
- 시스템/OS 관심은 반드시 **프로젝트, 수업, 학습, 오픈소스 경험**과 연결할 것
- 서비스 프로젝트를 넣더라도 “예쁜 UI”보다 **문제 정의, 구현, 검증, 역할, 배운 점**을 강조할 것

## 6. 콘텐츠 우선순위
포트폴리오 메인 페이지에서 중요한 순서:

1. 한 줄 포지셔닝
2. 핵심 요약(학력/목표 직무/강점)
3. 대표 프로젝트 3~5개
4. 기술 스택과 근거
5. 수상/문제 해결 이력
6. GitHub / 이력서 / 연락처

## 7. 프로젝트 선택 규칙
프로젝트 카드/상세에는 아래 요소가 있어야 한다.

- 문제 또는 목표
- 내가 맡은 역할
- 사용 기술
- 기술적으로 고민한 지점
- 결과
- 배운 점

없는 것은 억지로 채우지 말고 비워 두거나 TODO로 남겨라.
